# PRODUCT_SENSE.md

기술 판단보다 위에 있는 판단. **재미없으면 네트코드가 완벽해도 실패다** (CB-8).

---

## 이 게임이 이기는 지점

경쟁작(Among Us, Gartic Phone, skribbl.io, Hide.io 류)과 비교했을 때 우리가 가진 것:

1. **설치 0, 계정 0** — 링크 하나. 이게 전부다
2. **폰에서 제대로 됨** — 웹 P2P 게임 대부분이 모바일을 포기한다
3. **영원히 살아있음** — 정적 파일이라 유지비가 0이고, 방치해도 안 죽는다

우리가 못 가진 것:

- 매치메이킹 (아는 사람끼리만)
- 랭킹/진행도 (재방문 동기가 약함)
- 9명 이상

**그래서 타겟은 "이미 아는 사람 3~8명이 지금 같이 뭔가 하고 싶을 때"**다. 디스코드 켜놓고 "이거 해보자" 하는 상황. 랭킹 게임이 아니라 파티 게임이다.

## 재미 가설 (검증 필요)

플레이테스트에서 확인할 것들. **지금은 가설일 뿐이다.**

| # | 가설 | 어떻게 확인 |
|---|---|---|
| G1 | 소리(소음 방향)가 시각보다 긴장감을 만든다 | 소음 시스템 끈 버전과 비교 플레이 |
| G2 | 유령이 소리를 낼 수 있으면 잡힌 뒤에도 안 나간다 | 잡힌 후 이탈률 측정 (로컬 카운터) |
| G3 | 사물 빙의가 있으면 맵을 탐색하게 된다 | 빙의 사용 빈도 |
| G4 | 술래 시야가 원뿔이면 "등 뒤로 돌아가는" 플레이가 나온다 | 관찰 |
| G5 | 180초는 적당하다 | 라운드가 지루해지는 시점 관찰 |
| G6 | 럼블의 밀치기가 태그보다 재밌다 | 킬 중 밀어냄 비율 |

**G1이 틀리면 게임의 절반을 다시 설계해야 한다.** 그래서 exec-plan 002에서 가장 먼저 검증한다.

## 첫 5분 설계

사람이 이 게임을 계속할지는 첫 5분에 정해진다.

```
0:00  링크 클릭
0:03  로딩 끝, 이름 이미 채워져 있음
0:05  [시작] 누름
0:10  로비. 친구들 이름 보임
0:30  첫 라운드 시작 (숨는 쪽으로)
0:50  숨음. 발소리 들림 (술래가 가까이)
1:20  안 잡히고 버팀 → "어 재밌네"
3:30  라운드 끝. 다음 라운드 바로 시작
```

**0:50의 "발소리 들림"이 훅이다.** 여기서 심장이 뛰지 않으면 게임이 실패한 것이다.

그래서 우선순위:
1. 로딩 속도 (3초)
2. 입장 마찰 제거 (계정 없음)
3. 소음 피드백의 질

이 셋이 다른 모든 기능보다 먼저다.

## 하지 않기로 한 것과 그 이유

| 안 하는 것 | 이유 |
|---|---|
| 랭킹·전적 | 서버가 없다. 억지로 넣으려면 서버가 필요하고, 그건 CB-1을 깬다. **제품의 정체성을 바꾸느니 기능을 포기한다** |
| 총/원거리 무기 | 모바일 조준이 PC를 절대 못 이긴다. 크로스플랫폼 공정성이 깨진다 |
| 9명 이상 | 풀메시 n²가 8명이 한계. 억지로 늘리면 품질이 무너진다. **잘 되는 8명이 망가진 16명보다 낫다** |
| 커스터마이징 | 저장할 곳이 없다 |
| 봇/AI | 혼자 할 게임이 아니다. 혼자 하고 싶으면 다른 게임이 많다 |
| 광고/과금 | 서버비가 0원이라 수익화할 이유가 없다 |

## 성공의 정의

포트폴리오 프로젝트이자 실제로 플레이되는 게임이다. 둘 다 측정한다.

**포트폴리오로서:**
- 결정적 시뮬레이션 + 권위 서버 + 예측/재조정을 직접 구현한 사례
- P2P에서 정보 비대칭을 설계로 푼 사례 (DD-002)
- 문서 주도 개발의 실물

**게임으로서:**
- 친구 6명이 모여서 **3판 이상 연속으로** 한다
- 그중 누군가 "이거 또 하자"고 말한다
- 처음 들어온 사람이 설명 없이 한 판을 끝낸다

세 번째가 가장 어렵고 가장 중요하다.
