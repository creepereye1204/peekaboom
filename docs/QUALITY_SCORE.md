# QUALITY_SCORE.md

머지 전에 통과해야 하는 기준. **주관적 "좋아 보임"이 아니라 체크 가능한 항목**으로 만든다.

---

## 1. 자동 게이트 (CI에서 강제)

하나라도 실패하면 머지 불가.

| # | 항목 | 명령 | 기준 |
|---|---|---|---|
| A1 | 포맷 | `cargo fmt --all --check` | 차이 없음 |
| A2 | 린트 | `cargo clippy --all-targets -- -D warnings` | 경고 0 |
| A3 | 테스트 | `cargo test --workspace` | 전부 통과 |
| A4 | **좌표 유출** | `cargo test --test no_leak` | 통과 (H4) |
| A5 | **결정성** | `cargo test --test determinism` | 1000틱 후 상태 해시 일치 |
| A6 | 번들 크기 | `tools/check_size.sh` | WASM gzip ≤ 1.5 MB (H5) |
| A7 | 빌드 | `wasm-pack build --release` | 성공 |
| A8 | E2E | Playwright 2피어 시나리오 | 방 입장 + 1라운드 완주 |
| A9 | 매니페스트 | `tools/check_assets.sh` | 코드가 참조하는 모든 에셋이 매니페스트에 있음 (H7) |

A4와 A5가 이 프로젝트의 **핵심 불변식**이다. 다른 걸 다 포기해도 이 둘은 지킨다.

---

## 2. 수동 체크 (리뷰어 확인)

### 코드

- [ ] `crates/sim`에 `wasm32` 의존성이 없다 (네이티브 테스트 가능)
- [ ] 의존 방향이 단방향이다 (`sim` ← `net`/`render`/`input` ← `app`)
- [ ] `unsafe`가 없다. 있으면 design-doc 근거 + `// SAFETY:` 주석
- [ ] 역직렬화 경로에 `unwrap()`/`panic!`이 없다
- [ ] 부동소수점이 시뮬레이션 로직에 안 들어갔다 (렌더는 허용)
- [ ] JS가 세 가지 역할(Trystero/캔버스/오디오) 밖으로 안 나갔다

### 문서

- [ ] 구현한 product-spec / design-doc이 PR 본문에 링크됨
- [ ] 코드와 문서가 어긋나면 문서도 같은 PR에서 갱신됨
- [ ] 새 결정을 했으면 design-doc이 추가됨
- [ ] 새 에셋이면 매니페스트에 출처·라이선스 기록됨
- [ ] 미룬 게 있으면 tech-debt-tracker에 등록됨

### 정직성 (이게 제일 중요하다)

- [ ] **플레이스홀더가 없다.** 더미 데이터, `example.com`, 빈 함수, "TODO: 나중에"
- [ ] **숫자가 측정값이면 측정했다.** 추측이면 "미검증"이라고 적혀 있다
- [ ] **모바일 확인 여부가 사실대로 적혀 있다.** 안 했으면 "미확인"
- [ ] **에셋 파일이 실제로 존재한다.** 상상해서 경로를 쓰지 않았다

---

## 3. 모바일 체크 (UI를 건드린 PR)

- [ ] 360px 폭에서 UI가 겹치지 않는다
- [ ] 터치 타겟 ≥ 48×48 CSS px
- [ ] `env(safe-area-inset-*)` 적용
- [ ] 조이스틱 + 버튼 동시 입력이 동작한다
- [ ] 회전 시 게임이 안 멈춘다
- [ ] 흑백 스크린샷에서도 상태 구분이 된다 (색맹 대응)
- [ ] `prefers-reduced-motion`에서 흔들림/플래시가 꺼진다

기기가 없어서 확인 못 했으면 **"미확인"이라고 적는다.** 확인했다고 거짓말하는 것보다 미확인이 낫다.

---

## 4. 성능 체크 (렌더/시뮬을 건드린 PR)

- [ ] 드로우콜 ≤ 3
- [ ] 프레임 타임이 이전 대비 나빠지지 않았다 (디버그 패널 수치 비교)
- [ ] 프레임당 힙 할당이 없다 (버퍼 재사용)
- [ ] DOM 갱신이 값 변경 시에만 일어난다

## 5. 점수표 (참고용)

PR 리뷰에서 감을 잡기 위한 것. 자동 게이트를 대체하지 않는다.

| 영역 | 배점 | 보는 것 |
|---|---|---|
| 정직성 | 30 | 플레이스홀더 없음, 미검증 표시, 부채 등록 |
| 불변식 | 25 | A4/A5 유지, 의존 방향, 권위 모델 |
| 문서 일치 | 20 | 스펙↔구현, 결정 기록 |
| 모바일 | 15 | 터치, 레이아웃, 성능 |
| 코드 품질 | 10 | 가독성, 테스트, 네이밍 |

**정직성이 가장 높은 배점인 이유**: 이 프로젝트는 여러 세션에 걸쳐 진행된다. 다음 세션의 에이전트는 문서를 믿고 작업한다. 문서에 거짓이 하나 들어가면 그 위에 쌓인 모든 게 무너진다.

## 6. 리뷰에서 자주 나오는 반려 사유

실제로 자주 걸릴 것들을 미리 적어둔다:

1. "일단 동작하게" 하려고 `sim`에 `f32`를 씀 → 결정성 깨짐
2. 렌더러가 데이터를 갖고 있으면서 안 그리는 방식으로 fog 구현 → H4 위반
3. 에셋 파일 경로를 추측해서 씀 → 빌드 시점엔 안 걸리고 런타임에 깨짐
4. JS에 게임 상태를 둠 → 단일 진실 원칙 위반
5. `makeAction`으로 스냅샷 전송 → 신뢰성 채널이라 지연 누적
6. 모바일 확인 안 하고 "확인함"이라고 적음 → 신뢰 붕괴
7. 부채를 코드 주석으로만 남기고 트래커에 안 적음
