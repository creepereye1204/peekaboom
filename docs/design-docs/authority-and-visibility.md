# DD-002 · 호스트 권위와 피어별 가시성 필터링

- 상태: **채택됨**
- 관련: CB-3, H3, H4
- 대체: 없음

---

## 문제

숨바꼭질의 핵심 자산은 **숨은 사람의 좌표**다. 이게 새면 게임이 없다.

순진한 P2P 구현은 이렇게 한다:

```
각 피어: 내 위치를 매 틱 전체에 브로드캐스트
```

이러면 술래 클라이언트가 **모든 숨은 사람의 좌표를 이미 갖고 있다**. 렌더링에서 안 그릴 뿐이다. F12 → Network 탭 → DataChannel 메시지를 보면 끝이다. 개조 클라이언트를 만들 필요도 없다.

또 다른 문제: 누가 "나 안 잡혔어"를 스스로 선언하면, 잡혀도 안 잡혔다고 우길 수 있다.

## 결정

**단일 호스트 권위 + 피어별 가시성 필터링.**

1. 호스트 피어 하나가 유일한 시뮬레이션 진실을 갖는다
2. 클라이언트는 입력만 보낸다. 상태를 주장하지 않는다
3. 호스트는 각 피어에 대해 `sim.visible_to(peer)`를 계산하고, **그 피어가 볼 수 있는 엔티티만 담은 스냅샷**을 개별 생성한다

```
호스트 틱:
  collect_inputs()
  world.step(inputs)
  for peer in peers:
      vis = world.visible_to(peer)
      snapshot = encode_delta(world, vis, last_acked[peer])
      send(peer, snapshot)      // 각자 다른 내용
```

## 가시성 규칙

`visible_to(viewer)`가 포함시키는 것:

| 대상 | 조건 |
|---|---|
| 자기 자신 | 항상 |
| 같은 팀(잡힌 사람들) | 항상 |
| 다른 플레이어 | 시야각 안 + 시야거리 안 + 벽에 안 가림 |
| 다른 플레이어 (근접) | 반경 2타일 이내면 벽 뒤여도 "인기척" 마커만 (좌표 정밀도 1타일로 양자화) |
| 소음 이벤트 | 발생 위치 반경 6타일 이내면 방향만, 정확한 좌표 없이 |
| 맵 지형 | 항상 (정적이므로 비밀 아님) |
| 아이템 | 시야 안일 때만 |

**정밀도 양자화가 중요하다.** "근처에 누가 있다"를 알려주되 정확한 픽셀 좌표를 주지 않는다. 인기척은 게임성을 위해 필요하지만, 그게 곧 좌표 유출이 되면 안 된다.

시야 판정은 `sim` 안의 그리드 레이캐스트(DDA). 맵이 타일 기반이라 저렴하다. 8명 × 8명 = 64회 레이캐스트/틱, 30Hz에서 문제없는 수준이다. (미측정 — 벤치마크는 exec-plan 003에서)

## 스냅샷 델타와 소멸 처리

피어별로 "직전에 보낸 가시 집합"을 기억한다. 엔티티가 가시 집합에서 빠지면 `Despawn`을 보낸다. 클라이언트는 그 엔티티를 지운다.

주의할 함정: **갑자기 사라지면 "저쪽으로 갔구나"가 드러난다.** 그래서 시야에서 벗어난 엔티티는 즉시 지우지 않고, 마지막 목격 위치에 **고스트를 0.5초 남긴 뒤** 페이드아웃한다. 게임적으로도 자연스럽고(잔상), 정보 유출도 줄인다.

## 검토했으나 채택하지 않은 대안

### A. 완전 분산 + 암호학적 커밋먼트

각 피어가 자기 위치를 커밋(해시)만 뿌리고, 술래가 "여기 확인"하면 그 지점만 열어보는 방식. 진짜로 서버 없이 치트를 막을 수 있다.

기각 이유: 연속 이동을 커밋으로 표현하려면 틱마다 커밋 + 영역 증명이 필요하고, 이건 사실상 zk 회로 영역이다. 브라우저에서 30Hz로 돌릴 수 없다. 재미와 무관한 복잡도.

### B. 모든 피어가 같은 시뮬레이션 (lockstep)

결정적 시뮬레이션이 있으니 lockstep도 가능하다. 하지만 lockstep은 **모든 피어가 모든 입력을 받아야** 한다 → 모든 위치를 재구성할 수 있다 → CB-3 위반. 숨바꼭질에 lockstep은 구조적으로 안 맞는다.

### C. 술래만 권위

술래가 호스트면 "숨은 사람 좌표를 호스트가 다 안다" = 술래가 다 안다. 최악. 기각.

## 받아들인 리스크

**호스트는 치트할 수 있다.** 호스트 클라이언트를 개조하면 모든 좌표를 볼 수 있다. 서버가 없는 이상 구조적으로 못 막는다.

완화책:
- 호스트는 방을 만든 사람 = 보통 친구들을 초대한 사람. 사회적 신뢰가 1차 방어선
- UI에 호스트가 누군지 항상 표시한다 (숨기지 않는다)
- 랭킹/보상이 없으므로 치트 유인이 약하다

자세한 건 `docs/SECURITY.md` §3.

## 결과 검증 방법

- 통합 테스트: 술래가 아닌 피어의 수신 패킷을 덤프 → 숨은 사람 좌표가 포함되지 않음을 단언
- 이 테스트는 **CI 필수 통과 항목**이다. 깨지면 H4 위반이므로 머지 불가
