# DD-009 · 맵 설계 (손으로 만든다)

- 상태: **채택됨**
- 관련: PRODUCT_SENSE, DD-002, hide-and-seek.md

---

## 문제

절차적 생성인가, 손으로 만든 맵인가.

---

## 결정: 손으로 만든 맵 1개로 시작

v1은 **사람이 설계한 맵 한 개**다. 절차적 생성을 쓰지 않는다.

### 근거

숨바꼭질의 재미는 **맵을 외우는 것**에서 나온다.

- "저기 캐비닛 뒤가 비어 있다"
- "이 통로로 돌면 술래 등 뒤로 나온다"
- "3번 탈출구는 소리가 잘 안 들린다"

이런 지식이 쌓이는 게 실력이고, 실력 차이가 게임을 재밌게 만든다. **맵이 매번 바뀌면 이 축이 통째로 사라진다.**

절차적 생성은 "콘텐츠가 무한하다"를 주지만, 우리가 필요한 건 "한 맵을 열 번 하는 동안 계속 재밌다"이다. 다른 문제다.

부수적 이득: 생성 알고리즘·검증 로직·밸런스 튜닝이 전부 없어진다. 8~12개 방을 손으로 배치하는 게 훨씬 싸다.

### 언제 이 결정을 다시 여는가

한 맵을 20판쯤 했을 때 "지겹다"가 나오면 → **맵을 더 만든다.** 여전히 절차적 생성이 아니다. 맵 3~4개 로테이션이면 충분할 가능성이 높다.

## 맵 규격

| 항목 | 값 |
|---|---|
| 크기 | 64 × 40 타일 |
| 방 개수 | 8~12 |
| 빙의 오브젝트 | 40~60 |
| 탈출구 | 3 |
| 테마 | 사무실 (v1은 이것 하나) |

### 왜 128×128이 아니라 64×40인가

ARCHITECTURE 초안은 128×128이었는데 줄였다.

- 6명 기준 128×128(16384타일)은 **너무 넓다**. 술래가 사람을 못 만난다
- 180초 안에 술래가 맵을 훑을 수 있어야 긴장이 유지된다
- 걷기 속도 4타일/초 × 180초 = 720타일 이동. 64×40 맵의 대각선이 약 75타일이니 **왕복 4~5회** 가능한 크기다
- 좁은 맵이 스냅샷·타일 렌더링 비용도 줄인다

64×40은 16:10 비율이라 가로 화면에 잘 맞는다.

## 설계 규칙

### R1. 막다른 골목은 2개 이하

도망 경로가 항상 있어야 한다. 막다른 곳에 몰리면 게임이 아니라 처형이다.

예외로 2개를 두는 이유: **위험한 명당**이 있어야 재밌다. "저기 숨으면 안 걸리는데, 걸리면 끝"이라는 도박.

### R2. 모든 방은 출구 2개 이상 (R1의 2곳 제외)

### R3. 루프가 최소 3개

술래를 따돌리며 돌 수 있는 순환 경로. 이게 없으면 추격이 직선 달리기가 된다.

### R4. 시야 차단물을 통로 중간에 둔다

긴 직선 복도는 술래에게 너무 유리하다. 기둥·파티션·모서리로 끊는다.

### R5. 빙의 오브젝트는 방마다 성격이 다르게

- 사무실: 서류함, 파티션, 정수기
- 탕비실: 냉장고, 자판기
- 회의실: 의자 더미, 프로젝터 카트

같은 오브젝트가 전 맵에 깔리면 "어디든 똑같다"가 된다. 방마다 다르면 **어느 방에 숨었는지가 정보**가 된다.

### R6. 탈출구 3곳은 서로 최대한 멀게

한 곳을 지키면 나머지 둘이 열린다. 술래가 2명일 때(7명 이상)도 하나는 반드시 빈다.

### R7. 스폰 지점은 술래로부터 등거리

특정 시작 위치가 유리하면 안 된다.

## 데이터 형식

맵은 **코드가 아니라 데이터**다. 밸런스 조정이 잦을 것이므로 재컴파일 없이 바꿀 수 있어야 한다.

```
assets/maps/office.pkm   (PEEKABOOM Map)
```

바이너리 형식:

```
magic     4  "PKM1"
width     1
height    1
tiles     w*h   (u8: 0=바닥 1=벽 2=문)
n_objects 1
objects   [ u8 x, u8 y, u8 kind ]      # 빙의 오브젝트
n_exits   1
exits     [ u8 x, u8 y ]
n_spawns  1
spawns    [ u8 x, u8 y ]
```

64×40 기준 약 2.7 KB. 번들에 그대로 넣는다.

### 편집

Tiled(무료, 오픈소스)로 편집하고 `tools/convert_map.rs`로 `.pkm`을 만든다.
Tiled의 TMX는 XML이라 그대로 쓰면 파싱 코드와 용량이 늘어난다. 빌드 타임에 변환한다.

**맵 에디터를 직접 만들지 않는다** (product-specs/index.md의 범위 밖 목록).

## 검증

`tools/check_map.rs`가 규칙을 자동 검사한다. 맵을 바꿀 때마다 CI에서 돈다.

- [ ] R1: 막다른 방이 2개 이하인가 (그래프 차수 1인 노드 세기)
- [ ] R2: 나머지 방의 출구가 2개 이상인가
- [ ] R3: 순환 경로가 3개 이상인가 (사이클 기저 크기)
- [ ] R6: 탈출구 간 최단거리가 각각 20타일 이상인가
- [ ] R7: 스폰 지점들의 중심으로부터 분산이 임계 이하인가
- [ ] 모든 바닥 타일이 연결되어 있는가 (고립 구역 없음)
- [ ] 모든 빙의 오브젝트에 도달 가능한가

**사람이 눈으로 보고 "괜찮네" 하는 걸 신뢰하지 않는다.** 고립된 구역 하나가 라운드를 망친다.

## 시야 판정과의 관계

`sim::visible_to()`가 이 그리드에서 DDA 레이캐스트를 돈다(DD-002).

- 벽 타일이 시야를 막는다
- **문 타일(2)은 열린 상태면 안 막는다** — M4에서 문 상태를 월드에 추가
- 빙의 오브젝트는 시야를 막지 않는다 (막으면 오브젝트 뒤가 무적 은신처가 된다)

레이캐스트 비용: 8명 × 8명 = 64회/틱. 맵이 64×40이므로 한 레이의 최대 길이가 짧다. **미측정** — exec-plan 002에서 확인.
