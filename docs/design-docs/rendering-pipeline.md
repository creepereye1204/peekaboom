# DD-004 · 렌더링 파이프라인 (엔진 미채택, WebGL2 직접)

- 상태: **채택됨**
- 관련: H5, CB-4

---

## 문제

Rust로 브라우저 2D 게임을 그리는 방법이 여럿이다. 무엇을 쓸 것인가.

## 후보 비교

| | Bevy | macroquad | WebGL2 직접 (`web-sys`) |
|---|---|---|---|
| wasm-bindgen 상호운용 | 가능 | **어려움** (자체 JS 심, 플러그인 작성 필요) | 네이티브 |
| 번들 크기 | 큼 (ECS + 렌더 그래프 전체) | 작음 | **가장 작음** |
| 프레임 루프 제어 | 엔진 소유 | 엔진 소유 (async 루프) | **우리 소유** |
| 2D 스프라이트 작업량 | 거의 0 | 거의 0 | 800~1200줄 |
| 모바일 터치 | 지원 | 지원 | 직접 구현 |

## 결정

**WebGL2 직접 제어.** 엔진을 쓰지 않는다.

결정 요인 두 가지:

1. **Trystero 호출이 필수다** (ARCHITECTURE §3). macroquad는 wasm-bindgen을 쓰지 않아서 JS 라이브러리를 부르려면 별도 심을 직접 써야 한다. 그럴 거면 처음부터 wasm-bindgen 생태계에 있는 게 낫다.
2. **프레임 루프를 우리가 쥐어야 한다.** 고정 30Hz 시뮬 + 가변 렌더 + 네트워크 펌프를 한 루프에 엮어야 하는데, 엔진이 루프를 소유하면 계속 싸운다.

Bevy는 wasm-bindgen과 잘 맞지만 번들이 H5(1.5MB gzip)를 위협한다. 숨바꼭질 하나 만들자고 ECS 렌더 그래프를 지고 갈 이유가 없다.

## 파이프라인

```
sim::World (읽기 전용)
   │
   ▼
[컬링]  카메라 AABB ∩ 엔티티  +  VisibilitySet
   │
   ▼
[정렬]  y좌표 오름차순 (탑다운 뎁스)
   │
   ▼
[인스턴스 버퍼 채우기]  per-sprite: x, y, rot, scale, uv_rect, tint
   │
   ▼
[드로우]  아틀라스 바인딩 1회 → gl.drawArraysInstanced 1회
```

드로우콜 목표: **프레임당 3회 이하** (타일맵 1, 엔티티 1, UI 1).

### 텍스처 아틀라스

모든 스프라이트를 빌드 타임에 하나의 아틀라스로 합친다. 생성 스크립트: `tools/pack_atlas.rs` → 결과는 `docs/generated/asset-manifest.md`에 기록.

- 아틀라스 크기 2048×2048 상한 (구형 모바일 GPU 호환)
- 패딩 2px (밉맵/필터링 블리딩 방지)
- `NEAREST` 필터 — 픽셀아트 선명도 유지

### 타일맵

맵은 64×40 타일 (DD-009). 매 프레임 전부 그리지 않는다.

- 화면에 보이는 타일만 인스턴스 버퍼에 채운다 (보통 24×14 ≈ 336개)
- 정적이므로 카메라가 안 움직이면 버퍼 재사용

### Fog of War

`sim::visible_to()`가 준 가시 집합을 **R8 텍스처 (64×40)**로 업로드하고, 프래그먼트 셰이더에서 곱한다.

```glsl
float vis = texture(u_visibility, v_world_uv).r;
fragColor = base * mix(vec4(0.06,0.07,0.11,1.0), vec4(1.0), vis);
```

부드러운 경계를 위해 업로드 전에 `sim` 쪽에서 3×3 박스 블러 1패스. CPU에서 하는 게 GPU 패스 추가보다 싸다 (64×40 = 2.5K 샘플).

> 중요: fog는 **보기 좋으라고** 있는 게 아니다. 서버가 안 보내준 걸 안 그리는 것뿐이다. 렌더러가 데이터를 갖고도 가리는 구조면 DD-002 위반이다.

## 성능 예산 (목표, 미측정)

| 항목 | 예산 |
|---|---|
| 프레임 타임 (중급 안드로이드) | 16ms 이하 (60fps) / 최소 33ms (30fps) |
| 드로우콜 | ≤ 3 |
| 인스턴스 수 | ≤ 500 |
| 텍스처 메모리 | ≤ 16MB |

측정 전까지 이 숫자들은 **목표일 뿐 검증된 값이 아니다.** exec-plan 003에서 실기 측정.

## 트레이드오프 명시

직접 구현의 비용:

- 스프라이트 배칭, 아틀라스 패킹, 텍스처 로딩, 셰이더 관리를 우리가 짠다
- 파티클, 애니메이션 스테이트머신 같은 편의 기능이 없다
- 버그가 나면 우리 코드다 (장점이기도 하다)

이 비용을 감수하는 이유는 위 두 결정 요인 때문이다. 게임이 커져서 3D나 복잡한 이펙트가 필요해지면 이 결정을 다시 연다.
