# 제품 스펙 · 럼블 (Rumble)

두 번째 모드. 숨바꼭질의 반대편에 있다.

---

## 한 줄

**전원이 서로를 노린다. 안전 구역이 줄어들고, 마지막 1명이 남는다.**

숨바꼭질이 "숨는 게임"이라면 럼블은 "숨을 곳이 사라지는 게임"이다. 같은 맵, 같은 조작, 정반대 긴장감.

---

## 왜 이 모드가 있나

1. **인원이 적을 때**(3~4명) 숨바꼭질은 금방 끝난다. 럼블은 3명이어도 성립한다
2. **잡힌 사람이 기다리는 시간**이 숨바꼭질의 약점인데, 럼블은 라운드가 짧아(2~3분) 회전이 빠르다
3. 같은 시뮬레이션·네트워크 코드를 재사용한다. `RuleSet`만 바꾸면 된다 — 추가 비용이 작다

---

## 라운드 흐름

```
로비 → 산개 10초 → 링 1 (40초) → 링 2 (35초) → 링 3 (30초) → 링 4 (수축 지속) → 결과
```

안전 구역(링)은 매 단계 중심이 **랜덤하게 조금씩 이동**하면서 줄어든다. 완전 동심원이면 지루하다.

| 링 | 반경 | 유지 | 수축 |
|---|---|---|---|
| 시작 | 맵 전체 | 10초 | — |
| 1 | 45타일 | 40초 | 12초 |
| 2 | 28타일 | 35초 | 10초 |
| 3 | 16타일 | 30초 | 8초 |
| 4 | 7타일 | — | 6초 |
| 최종 | 0 | — | — |

링 밖에 있으면 **초당 체력 8 감소** (체력 100). 수축이 진행될수록 피해가 커진다(링4 기준 초당 20).

---

## 전투

무기가 아니라 **태그**다. 총을 안 넣는 이유는 아래 "만들지 않는 것" 참조.

| 행동 | 조작 | 규칙 |
|---|---|---|
| 태그 | 자동 | 반경 1.0타일. 상대 체력 -35, 나 +10 (최대 100) |
| 대시 | Shift / 버튼 | 1.2초 속도 7.0. 쿨다운 5초 (숨바꼭질보다 짧음) |
| 밀치기 | E | 전방 2타일 내 상대를 3타일 밀어냄. 링 밖으로 밀 수 있다. 쿨다운 6초 |
| 빙의 | E (오브젝트 위) | 가능하지만 **5초 제한**. 이후 자동 해제 + 큰 소음 |

**밀치기가 럼블의 핵심 기술이다.** 직접 때려서 이기는 것보다 링 밖으로 밀어내는 게 강하다. 지형과 타이밍을 읽는 재미가 여기서 나온다.

## 시야

숨바꼭질과 달리 **링 안의 모든 플레이어가 미니맵에 점으로 표시**된다 (정확한 좌표 아님, 2타일 단위 양자화).

> DD-002의 가시성 필터링은 여전히 적용된다. 럼블에서는 "링 안 = 가시"라는 규칙이 추가될 뿐, 호스트가 필터링한다는 구조는 같다. 필터 규칙이 모드별 파라미터다.

---

## 밸런스 초기값

**미검증 추측치.**

| 인원 | 링 타이밍 | 비고 |
|---|---|---|
| 3 | 전체 ×0.7 | 너무 길면 늘어짐 |
| 4~6 | 표준 | |
| 7~8 | 전체 ×1.2 | 초반 조우가 너무 잦음 |

체력 100 / 태그 35 = 3번 맞으면 죽는다. 이게 너무 빠른지 느린지는 플레이테스트에서.

---

## 만들지 않는 것

- **총·원거리 무기** — 넣는 순간 조준이 게임의 전부가 되고, 모바일 터치 조준은 키보드+마우스를 절대 못 이긴다. 크로스플랫폼이 깨진다. 근접 태그는 폰에서도 공평하다
- **아이템/루팅** — 라운드가 2~3분인데 루팅할 시간이 없다
- **팀 럼블** — v1 범위 밖. 개인전만
- **부활** — 죽으면 유령. 숨바꼭질과 동일하게 소리 한 번 낼 수 있다

---

## 구현 관점

`sim::RuleSet`으로 두 모드를 표현한다. 별도 코드 경로를 만들지 않는다.

```rust
pub struct RuleSet {
    pub mode: Mode,                  // HideAndSeek | Rumble
    pub round_secs: u16,
    pub seeker_count: u8,            // Rumble이면 0
    pub ring: Option<RingSchedule>,  // HideAndSeek이면 None
    pub visibility: VisibilityRule,  // ConeAndProximity | InsideRing
    pub tag_damage: Option<u8>,
    pub possess_max_secs: Option<u8>,
}
```

모드가 늘어날 때 `RuleSet` 필드가 계속 늘면 설계가 틀린 것이다. 그때는 컴포넌트 조합으로 리팩터링한다 — 하지만 **모드 2개일 때 미리 추상화하지 않는다.**
