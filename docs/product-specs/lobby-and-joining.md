# 제품 스펙 · 로비와 입장

**이 게임에서 가장 중요한 화면.** 여기서 막히면 게임을 해보지도 못한다.

---

## 성공 기준

> 친구가 보낸 링크를 폰에서 열고 **30초 안에** 같은 방에 들어가 있다. 계정 없이.

이 문장이 스펙 전체를 지배한다.

---

## 입장 흐름

```
링크 클릭
   │
   ▼
[로딩]  WASM 다운로드 + 초기화       ← 여기서 3초 넘으면 이탈
   │
   ▼
[닉네임]  자동 생성된 이름이 이미 채워져 있음 ("초록너구리")
   │       그냥 [시작] 누르면 됨. 바꾸고 싶으면 탭
   ▼
[연결중]  Trystero 방 접속 + 피어 핸드셰이크
   │
   ▼
[로비]   플레이어 목록 / 모드 선택 / 준비 / 시작
```

**계정 없음. 이메일 없음. 약관 동의 없음.** 저장할 서버가 없으니 물어볼 것도 없다.

### URL 구조

```
https://<user>.github.io/peekaboom/#r=A7K3QX
                                     └ 6자 방 코드 (대문자+숫자, 혼동 문자 제외: I,O,0,1)
```

- 해시 프래그먼트를 쓰는 이유: GitHub Pages는 SPA 라우팅을 지원하지 않는다. `#`이면 404가 안 난다
- 코드 없이 접속하면 → "방 만들기" 또는 "코드 입력" 선택 화면
- 방을 만들면 즉시 URL이 갱신되고(`history.replaceState`), **공유 버튼**이 뜬다

### 공유

| 환경 | 동작 |
|---|---|
| 모바일 (Web Share API 지원) | `navigator.share()` → 카톡/메신저 바로 뜸 |
| 그 외 | 클립보드 복사 + "복사됨" 토스트 |
| 항상 | 방 코드 6자를 크게 표시 (말로 불러줄 수 있게) |

## 로비 화면

```
┌────────────────────────────────────┐
│  방 코드  A7K3QX        [공유]  ⚙  │
├────────────────────────────────────┤
│  ● 초록너구리 (나)          호스트 │
│  ● 붉은수달                   준비 │
│  ● 파란고양이               대기중 │
│  ○ ...                             │
├────────────────────────────────────┤
│   [ 숨바꼭질 ]   [  럼블  ]        │  ← 호스트만 변경 가능
├────────────────────────────────────┤
│         [   준비 완료   ]          │
│   호스트: [ 게임 시작 (3/3) ]      │
└────────────────────────────────────┘
```

- 호스트에게 **왕관 아이콘** — 누가 심판인지 숨기지 않는다 (SECURITY.md §3)
- 3명 미만이면 시작 버튼 비활성 + "2명 더 필요해요"
- 8명 차면 "방이 가득 찼어요"로 추가 입장 거부
- 각 플레이어 옆에 **핑 표시** (초록 <80ms / 노랑 <160ms / 빨강 그 이상)

## 연결 실패 처리

여기가 P2P 게임이 사람을 잃는 지점이다. **정직하고 구체적으로 말한다.**

| 상황 | 감지 | 메시지 | 다음 행동 |
|---|---|---|---|
| 시그널링 릴레이 접속 실패 | 5초 내 릴레이 소켓 미개통 | 조용히 다음 전략으로 폴백 (Nostr → MQTT) | 자동 |
| 두 전략 다 실패 | 10초 | "매치메이킹 서버에 연결이 안 돼요. 수동 연결을 써보세요." | [수동 연결] 버튼 |
| 피어 연결 실패 (NAT) | SDP 교환은 됐는데 15초간 DataChannel 미개통 | "이 네트워크에서는 직접 연결이 안 돼요. 와이파이 대신 셀룰러(또는 그 반대)로 시도해보세요." | [재시도] / [TURN 설정] |
| 방 코드가 틀림 | 20초간 피어 0명 | "이 코드로 만든 방에 아무도 없어요. 코드를 다시 확인해주세요." | [코드 다시 입력] |
| 호스트 이탈 | `onPeerLeave` | "호스트가 나가서 <이름>이 호스트가 됐어요" (토스트) | 자동, 게임 계속 |

**절대 하지 않는 것**: "연결에 실패했습니다. 다시 시도해주세요." 같은 무의미한 메시지. 무엇이 실패했고 사용자가 뭘 할 수 있는지 항상 말한다.

### 수동 연결 (최후의 경로)

공개 릴레이가 전부 죽어도 게임은 돌아가야 한다 (CB-5).

```
호스트: [수동 연결] → 긴 코드 생성 (Base64 SDP, 압축 후 ~700자)
        → 카톡으로 붙여넣기
게스트: 코드 입력 → 응답 코드 생성 → 호스트에게 다시 붙여넣기
        → 연결
```

못생겼다. 인정한다. 3명 이상이면 매우 번거롭다. 그래도 남긴다. **이 경로는 UI 완성도보다 존재 자체가 가치다.**

## TURN 설정 (고급)

⚙ 설정에 "고급 → TURN 서버" 항목. 대칭 NAT 환경 사용자가 자기 TURN을 넣을 수 있다.

```
urls:       turn:example.com:3478
username:   ...
credential: ...
```

- 값은 `localStorage`에만 저장. 어디로도 전송하지 않는다
- 기본값 비어있음. **우리는 TURN을 제공하지 않는다** (H1)
- 안내 문구: "직접 연결이 안 되는 네트워크에서만 필요해요. 무료 TURN 서비스도 있습니다." + Cloudflare/Open Relay 링크

## 재접속

새로고침하면 같은 URL이므로 같은 방으로 자동 재입장한다. 닉네임은 `localStorage`에서 복원.

라운드 진행 중 재입장하면 → 유령으로 합류, 다음 라운드부터 정상 참여.
