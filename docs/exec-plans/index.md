## 규칙

- 파일명: `NNN-<slug>.md`, 번호는 순차. 건너뛰지 않는다
- 진행 중이면 `active/`, 끝나면 `completed/`로 옮긴다 (지우지 않는다)
- 각 계획에는 **완료 조건**과 **실패 분기**가 반드시 있다
- 측정이 산출물인 계획에는 **기록란**이 있다. 비워둔 채 완료 처리하지 않는다

## 순서의 논리

```
리스크가 큰 것 → 재미의 핵심 → 기기 대응 → 범위 완성
```

흔한 실패 패턴은 반대로 가는 것이다. 예쁜 메뉴와 캐릭터 애니메이션을 먼저 만들고, 마지막에 "어? 모바일에서 연결이 안 되네"를 발견한다.

그래서 **001은 못생긴 사각형 두 개로 실제 폰 연결만 확인한다.** 게임을 만들지 않는다.

## 각 계획의 진짜 산출물

체크리스트를 다 채우는 게 목적이 아니다. 각 계획에는 **답해야 할 질문**이 하나씩 있다:

| # | 진짜 산출물 |
|---|---|
| 001 | 통신 3사 × 와이파이 **연결 매트릭스** (실측) |
| 002 | **G1 검증 실험 결과** (소리 끔 / 화살표 끔 조건 비교) |
| 003 | **성능 측정 매트릭스** — TD-006의 모든 추정치를 실측으로 교체 |
| 004 | **플레이테스트 기록** — TD-008의 밸런스 추측치 첫 실측 |

코드는 그 답을 얻기 위한 수단이다.
