# 004 · 게임으로 성립시키기

- 상태: **대기** (003 완료 후)
- 마일스톤: M4
- 목표: **친구 6명이 모여 3판 연속으로 하고, 누군가 "또 하자"고 말한다**

---

## 왜 이게 마지막 큰 계획인가

001은 연결, 002는 재미의 핵심, 003은 기기 대응을 확인했다. 004는 그것들을 **게임**으로 묶는다.

여기까지 오면 남은 건 규칙의 완성도와 마감이다. 새로운 기술 리스크는 없다.

---

## 체크리스트

### 1. 숨바꼭질 전체 규칙 (product-specs/hide-and-seek.md)

- [ ] 라운드 흐름: 숨는 시간 20초 → 추격 180초 → 결과 10초
- [ ] 술래 배정 + 다음 술래 = **마지막에 잡힌 사람** (빨리 잡히면 손해)
- [ ] 사물 빙의 — E로 오브젝트 변신, 해제 0.5초
- [ ] 대시 — 1.2초 속도 7.0, 쿨다운 8초, 큰 소음
- [ ] 탈출구 개방 — 3초 길게 누르기, 지속 소음
- [ ] 술래 스캔 — 3초 충전, 반경 6타일 빙의 오브젝트 0.6초 반짝, 쿨다운 25초
- [ ] **유령** — 자유 이동, 3초 쿨다운으로 "쿵" 1회, 유령끼리 채팅
  - [ ] 유령 쿵이 진짜 발소리와 구분되지 않아야 한다 (DD-008, 의도된 설계)
- [ ] 승패 판정 + 결과 화면

### 2. 맵 (DD-009)

- [ ] 사무실 맵 1개, 64×40, 방 8~12개
- [ ] 빙의 오브젝트 40~60개, 방마다 성격 다르게 (R5)
- [ ] 탈출구 3곳, 서로 20타일 이상 (R6)
- [ ] `.pkm` 형식 + `tools/convert_map.rs` (Tiled → pkm)
- [ ] `tools/check_map.rs` 전 규칙 통과 — CI 연동
  - [ ] 특히 **고립 구역 없음**. 하나만 있어도 라운드가 망가진다

### 3. 호스트 이양 (DD-007)

- [ ] 사전순 최소값 선출
- [ ] `HostShadow` 2초 주기, 4타일 양자화, 후보 호스트 1명에게만
- [ ] `HostHandoff` 브로드캐스트 + resume_tick 되감기
- [ ] `tests/netsim.rs` 시나리오 5개 (DD-007 테스트 요구사항)
  - [ ] Shadow를 못 받은 피어가 호스트가 되는 폴백 포함

### 4. 로비 · 온보딩 (lobby-and-joining.md, new-user-onboarding.md)

- [ ] 로비 화면 — 플레이어 목록, 핑 표시, 호스트 왕관, 준비/시작
- [ ] 3명 미만 시작 불가 + "2명 더 필요해요"
- [ ] 8명 차면 입장 거부
- [ ] 공유 — `navigator.share` → 클립보드 폴백, 방 코드 크게 표시
- [ ] **연결 실패 처리 5종** — 전부 구체적 문구로
  - [ ] 릴레이 실패 → 조용히 MQTT 폴백
  - [ ] 둘 다 실패 → 수동 연결 안내
  - [ ] NAT 실패 → "와이파이 대신 셀룰러로 시도해보세요"
  - [ ] 빈 방 → "이 코드로 만든 방에 아무도 없어요"
  - [ ] 호스트 이탈 → 토스트
  - [ ] **"연결에 실패했습니다. 다시 시도해주세요." 같은 문구 금지**
- [ ] 첫 라운드 힌트 7종, 각 한 문장, 자동 소멸, 닫기 버튼 없음
- [ ] 첫 접속자는 첫 라운드에 술래 안 시킴 (다른 후보가 있으면)
- [ ] 자동 닉네임 `<색깔><동물>`, 이미 채워진 상태

### 5. 럼블 (product-specs/rumble.md)

- [ ] `RuleSet`으로 표현. **별도 코드 경로를 만들지 않는다**
- [ ] 링 수축 스케줄 (중심이 매 단계 조금씩 이동)
- [ ] 링 밖 체력 감소 (초당 8 → 링4에서 20)
- [ ] 태그 (반경 1.0, -35 / +10)
- [ ] **밀치기** (전방 2타일, 3타일 밀어냄) ← 이 모드의 핵심 기술
- [ ] 빙의 5초 제한
- [ ] 미니맵 — 링 안 플레이어 2타일 양자화 점
  - [ ] 가시성 필터링은 여전히 호스트가 한다. 규칙만 `InsideRing`으로 바뀐다

### 6. 수동 연결 폴백 (CB-5)

- [ ] SDP → Base64 압축 코드 생성/입력 UI
- [ ] 못생겨도 된다. **존재 자체가 가치다**

## 완료 조건

1. 숨바꼭질 한 라운드가 처음부터 끝까지 진행된다 (설명 없이 들어온 사람 포함)
2. 럼블 한 라운드가 진행된다
3. 호스트가 중간에 나가도 게임이 이어진다 (실제로 탭을 닫아서 확인)
4. 맵 검증이 CI에서 통과한다
5. **친구 6명 실플레이에서 3판 연속** — PRODUCT_SENSE의 성공 정의

5번이 이 계획의 목적이다. 1~4는 수단이다.

## 플레이테스트 기록란

```
날짜:
인원:
연속 플레이 판수:
"또 하자" 발화: 있음 / 없음

관찰된 문제:
밸런스 조정 필요 항목:
```

### 밸런스는 여기서 처음 실측된다

product-specs의 모든 숫자가 **미검증 추측치**다 (TD-008). 이 플레이테스트가 첫 실측이다.

특히 확인할 것:

| 항목 | 현재값 | 의심 |
|---|---|---|
| 추격 180초 | 추측 | 지루한가 / 짧은가 |
| 술래 속도 4.4 vs 숨는 쪽 4.0 | 추측 | 차이가 너무 작은가 |
| 잡기 반경 1.2타일 | 추측 | "분명 잡았는데"가 자주 나오는가 (CB-2) |
| 7명 이상 술래 2명 | 추측 | 6명에서도 2명이 나은가 |
| 럼블 체력 100 / 태그 35 | 추측 | 3방이 빠른가 느린가 |
| 빙의 오브젝트 40~60개 | 추측 | 너무 많아서 술래가 포기하는가 |

## 하지 않는 것

PRODUCT_SENSE의 "하지 않는 것" 그대로:

- 랭킹·전적 (서버 없음)
- 총·원거리 무기 (모바일 조준이 PC를 못 이김)
- 9명 이상 (풀메시 한계)
- 커스터마이징, 봇, 음성 채팅, 맵 에디터, 수익화

**"나중에"가 아니라 "안 함"이다.**

추가로 이 계획에서 미루는 것:

- 맵 2개 이상 → 1개가 지겨워진 게 확인된 뒤
- 관전자 모드 → 유령이 겸함
- 리플레이 → 결정적 시뮬 덕에 가능하지만 우선순위 낮음
