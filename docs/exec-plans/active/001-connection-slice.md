## 왜 이걸 먼저 하나

이 프로젝트의 최대 미지수는 "실제 모바일 네트워크에서 P2P가 되는가"다. 안 되면 나머지 설계가 전부 무의미하다.

게임을 만들지 않는다. **네모 두 개면 충분하다.**

## 연결 검증 매트릭스

각 칸에 ✅/❌ + RTT(ms) + 비고를 채운다. **추측으로 채우지 않는다.**

| 피어 A \ 피어 B | 집 와이파이 | SKT LTE/5G | KT LTE/5G | LGU+ LTE/5G | 카페 와이파이 | 회사/학교망 |
|---|---|---|---|---|---|---|
| 집 와이파이 | | | | | | |
| SKT | | | | | | |
| KT | | | | | | |
| LGU+ | | | | | | |
| 카페 와이파이 | | | | | | |
| 회사/학교망 | | | | | | |

**중요**: 같은 와이파이 안의 두 기기는 거의 항상 성공한다. 그건 검증이 아니다. **다른 네트워크 간 조합**이 진짜 데이터다.

브라우저도 나눠서: Chrome/Android, Safari/iOS 최소 각 1대.

## 완료 조건

1. GitHub Pages URL을 폰에서 열면 사각형이 움직인다
2. 두 번째 폰(**다른 네트워크**)에서 같은 URL을 열면 사각형 두 개가 보인다
3. 위 매트릭스가 최소 8칸 채워졌다
4. RTT와 릴레이 상태가 디버그 패널에 실측으로 표시된다

## 알려진 함정

- iOS Safari에서 `AudioContext`/`wakeLock`은 아직 안 건드린다 (범위 밖). 단 백그라운드 전환 시 연결이 끊기는지는 **관찰해서 기록**한다
- GitHub Pages는 첫 배포 후 반영까지 몇 분 걸린다. 캐시 때문에 구버전을 보고 "안 된다"고 착각하기 쉽다 → `index.html`에 빌드 해시를 표시해둔다
- Trystero를 CDN으로 불러오면 빠르지만, 우리는 번들에 포함한다 (SECURITY.md §6). 처음부터 그렇게 한다
