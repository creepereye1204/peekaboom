- 상태: **대기** (001 완료 후 착수)
- 마일스톤: M2
- 목표: **소음 시스템이 실제로 긴장감을 만드는지 확인한다**

---

## 왜 이걸 하나

001이 "연결이 되는가"를 물었다면 002는 **"재밌는가"**를 묻는다.

기술적으로 완벽해도 재미없으면 실패다 (CB-8). 그리고 이 게임의 재미 가설은 하나에 걸려 있다:

> **PRODUCT_SENSE G1** — 소리(소음 방향)가 시각보다 긴장감을 만든다

G1이 틀리면 DD-002(가시성 필터링)와 DD-008(오디오)이 세운 정보 구조 전체를 다시 짜야 한다. **그러니 예쁜 걸 만들기 전에 이것부터 안다.**

## G1 검증 실험 ← **이 계획의 진짜 산출물**

4명 이상 모아서, 3가지 조건으로 각 3라운드.

| 조건 | 소리 | 화살표 |
|---|---|---|
| A (기준) | 켬 | 켬 |
| B | **끔** | 켬 |
| C | 켬 | **끔** |

`?audio=0` / `?arrows=0` 쿼리로 토글할 수 있게 만들어둔다.

### 측정 (추측으로 채우지 않는다)

| 항목 | 방법 |
|---|---|
| 술래 첫 발견까지 시간 | 로컬 카운터 → 디버그 패널 |
| "어디 있는지 모르겠다" 발화 | 관찰자가 수기 기록 |
| 긴장감 주관 평가 | 라운드 후 1~5 구두 |
| 잡힌 후 이탈률 (G2) | 잡힘 → 탭 닫기까지 시간 |
| 빙의 사용 빈도 (G3) | 카운터 |

### 결과 해석

| 결과 | 판단 | 다음 |
|---|---|---|
| B가 A보다 뚜렷이 덜 긴장됨 | **G1 확인.** 설계대로 | M3 진행 |
| B와 A가 비슷 | 소리는 장식. 화살표가 실제 채널 | DD-008 재작성. 시각 중심으로 정보층 재설계 |
| C가 A보다 재밌음 | 화살표가 오히려 긴장을 깎음 | 화살표를 접근성 옵션으로 내리고 소리를 주 채널로 승격 |
| A/B/C 모두 "술래가 답답함" | 정보량 자체가 부족 | 인기척 반경·강도 단계 튜닝. **필터링 자체는 포기하지 않는다** |

마지막 줄이 중요하다. 답답하다고 좌표를 주기 시작하면 게임이 사라진다(CB-3).
